C. Detailed Bug & Findings Report

BUG-001: Cloud OCR Processing Fallback to Client Heuristics
MEDIUM SEVERITY
Module: Sales / Masters / Purchases — Document OCR Uploader
Classification: Frontend / Integration
Description: DocumentOcrUploader provides an intuitive scanning interface and extracts metadata from filenames and regex patterns. However, full optical character recognition from binary images relies on client-side regex parsing rather than a server-side Tesseract / Cloud Vision API.
Steps to Reproduce: Open Customer/Vendor/Sale screen -> Click 'Scan & Upload (OCR)' -> Upload arbitrary scanned image.
Expected: Server-side OCR engine parses raw pixel text buffers.
Actual: Heuristic regex parser derives party name and seed hash amounts for form auto-fill.
BUG-002: Remote Supabase Query Latency on User Authentication
MEDIUM SEVERITY
Module: Identity / Auth Service
Classification: Database / Performance
Description: Backend E2E query performance logs captured Slow query detected (duration > 1000ms) on SELECT ... WHERE LOWER(email) = LOWER() due to remote network roundtrip latency and absence of a functional expression index on LOWER(email).
Steps to Reproduce: Execute npm run test:e2e against remote Supabase database.
Expected: Query execution time < 50ms.
Actual: Query takes 1020ms-1156ms under remote latency conditions.
BUG-003: WhatsApp Notification Delivery Mode
LOW SEVERITY
Module: Global / WhatsApp Notifications
Classification: Integration / Cloud Architecture
Description: WhatsApp triggers construct client-side wa.me URL schemes opening WhatsApp Web / Mobile app. Background unattended automated SMS/WhatsApp delivery (e.g. overnight low stock batch alerts) requires an active user interaction rather than headless cloud webhook dispatch.
Steps to Reproduce: Trigger low stock alert or payment reminder from the UI.
Expected: Direct background cloud delivery or client intent.
Actual: User browser opens WhatsApp Web with pre-filled message text for manual submission.
BUG-004: In-Memory Mock Fallback Handling during Backend Offline State
LOW SEVERITY
Module: Frontend API Services & MockDatabaseService
Classification: Frontend / UX
Description: When the backend API is offline, the frontend seamlessly switches to local state. However, background debug logs log [MockDatabaseService] loadX fallback: A network error occurred in console output.
Expected: Silent offline mode without repetitive debug log warnings.
Actual: Console outputs HTTP 400 fallback traces (does not affect UI stability).
